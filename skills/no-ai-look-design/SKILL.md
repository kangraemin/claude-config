# AI 티 안 나는 디자인

왜 이 스킬이 있나
- 2026-10-21 제주 데이터 사이트 홈을 사용자가 폰으로 보고 "진심 끔찍함", "ui 이게 뭐임".
- 문제: 요소 과다, 한 문장 안 주황/검정·굵기 섞기, 주황 남발, 카드마다 미니 대시보드, 깨알 도식, 크기 제각각 카드.
- 같은 화면에 LLM 블라인드 검사는 8/10을 줬다. LLM 점수는 사용자 눈과 맞지 않는다.

AI 티의 원인
- 모델은 학습 데이터의 평균으로 수렴한다(Anthropic 'distributional convergence').
- "멋지게", "프리미엄하게"라고 하면 더 평균으로 간다.
- 고치는 법은 더하기가 아니라 빼기, 그리고 실서비스 구조를 그대로 따라 하기다.

## 1. 체크리스트 (숫자로 잰다)

`scripts/ai_look_check.py`가 굵게 표시한 항목을 잰다. 기준은 폰(390px) 기준.

글자
- **13px 미만 글자 블록 3개 이하.** 캡션·법적 고지 말고는 없다. 폰에서 11~12px은 사용자가 못 읽는다.
- **고유 글자 크기 6개 이하.** 눈에 보이는 일은 2~3개 크기가 한다(큰 것 하나, 본문, 작은 것). 12.5·11.5 같은 반 픽셀 크기는 결정 안 한 흔적.
- **고유 굵기 3개 이하.** 예: 400·600·800. 본문은 400~500, 한국어는 500 권장.
- **한 문장(블록) 안에 색·굵기 다른 조각 0개.** 숫자만 주황, 한 단어만 굵게, 앞머리만 다른 색 금지. 강조는 문장 순서·크기·줄바꿈으로 한다.
- 제목에서 한 단어만 색·기울임·밑줄로 강조 금지.
- 제목 위 작은 라벨(eyebrow, "43개 읍면동 · …")·대문자 자간 라벨·pill 배지 금지. 그 정보는 제목이나 첫 문장에 넣거나 버린다.
- 'A · B · C' 가운뎃점 나열 메타 줄 금지(로컬 frontend-design의 2026 AI 군집).

색
- **강조색(채도 45% 이상) 요소: 첫 화면 3개 이하, 페이지 전체 8개 이하.** 토스처럼 한 화면 강조는 주 행동 하나 + 많아야 하나.
- **강조 색상 계열 2개 이하.** 브랜드색 하나 + 의미색(오류 빨강 등) 하나.
- 본문은 진한 잉크색. 회색 본문, 색 배경 위 회색 글자 금지.
- 그라디언트 0개(사진 위 글자 받침 스크림 하나만 예외). 쉬고 있는 요소에 그림자·빛번짐 금지.
- 보라·남색, 크림+테라코타(#F4F1EA·#D97757), 검정+형광 강조는 AI 기본값. 브리프가 요구할 때만.

카드·구성
- **카드 안 카드 0개.**
- **카드 하나 안 글자 조각 6개 이하.** 카드마다 숫자·라벨·막대·미니 지도를 넣은 '미니 대시보드' 금지. 카드는 제목 + 한 줄 + (그림 하나)면 충분.
- **같은 줄 카드 크기 3종류 이하**, 될 수 있으면 1종류. 크기를 다르게 할 거면 하나만 확실히 크게(2배 이상).
- 같은 크기 아이콘+제목+설명 카드 3개 줄, 큰 숫자+작은 라벨 '히어로 지표' 템플릿 금지.
- **카드 한쪽만 두꺼운 색 테두리 0개.**
- **작은 svg 도식(스파크라인·진행 링·깨알 막대) 4개 이하.** 내용 대신 장식으로 쓰지 않는다. 도식을 넣으려면 화면 폭 대부분을 쓰는 크기로 하나.
- **이모지 아이콘 0개.** 아이콘은 한 세트, 같은 굵기.
- 01/02/03 번호는 순서 자체가 정보일 때만.
- 모든 요소 같은 큰 radius 금지. radius는 2종 이하(예: 카드 12, 버튼 12 또는 완전 원형).

폰 화면
- **가로 넘침 0개.**
- **고정 하단바·헤더에 가려진 요소 0개**(페이지 맨 끝에서). 하단바 높이만큼 아래 여백.
- 터치 영역 44px 이상. 첫 화면에 방문자 목적 하나(주 행동 하나).

문구
- 로고 가리기 테스트: 문구가 경쟁 서비스에도 그대로 맞으면 다시 쓴다.
- 지어낸 둥근 숫자(10배, 99.9%) 금지. 실제 숫자는 출처·기준(무엇 대비)을 같은 문장에.
- 뜻에 영향 없는 단어 빼기(토스 '잡초 뽑기'). 바텀시트·카드 제목은 한 줄.

## 2. 작업 순서

1. **레퍼런스 실서비스 2~3곳을 같은 폭(390px)으로 캡처한다.**
   - 같은 카테고리 실제 서비스를 고른다. 예: 지역·여행 정보 → 당근 동네생활·네이버 지도 장소 탭·마이리얼트립, 금융·숫자 → 토스, 커머스·큐레이션 → 29CM·무신사, 콘텐츠 → 토스피드·브런치.
   - Playwright로 `page.screenshot`(로그인 필요 없는 공개 페이지). 이미지 생성 금지, 실제 캡처만.
   - 캡처 확인은 서브에이전트에 맡기고 글로 받는다(메인 컨텍스트에 이미지 쌓지 않음).
2. **구조만 따라 한다.** 레퍼런스에서 적어 온다:
   - 첫 화면에 몇 개 덩어리가 있나, 글자 크기 몇 단계, 강조색이 몇 군데, 카드 한 장에 글자 몇 줄.
   - 우리 화면을 그 숫자에 맞춘다. 색·글꼴은 우리 것, 밀도와 위계는 레퍼런스 것.
3. **덜어낸다(먼저 지우고 필요한 것만 다시).**
   - 강조색을 전부 검정으로 바꾸고, 아이콘·배지·eyebrow·작은 숫자 칩을 전부 지운다.
   - 방문자 목적 하나를 정하고 그 목적에 필요한 것만 되살린다. 주 버튼 하나만 강조색.
   - 카드마다 넣은 숫자·도식은 상세 화면으로 보낸다. 홈에는 제목 + 한 줄.
   - 문장은 반으로 줄이고 한 번 더 줄인다.
4. **숫자 검사를 돌린다.**
   ```bash
   python3 ~/.claude/skills/no-ai-look-design/scripts/ai_look_check.py <URL|html경로> --width 390 --json out.json --shot out.png
   ```
   - FAIL이 하나라도 있으면 고친다. 브리프가 요구해서 남기는 항목은 이유를 보고에 적는다.
   - 데스크톱도 쓰면 `--width 1280 --height 800`으로 한 번 더.
   - PASS는 '나쁜 신호 없음'일 뿐이다. 좋다는 뜻이 아니다.
   - 기준은 '목적 하나인 홈·앱 화면'용이다. toss.im 마케팅 긴 페이지도 tiny_text 59·font_sizes 20·gradients 21로 FAIL이 많다(2026-10-21 측정, 캐러셀·숨은 슬라이드 포함). 긴 마케팅 페이지에선 mixed_blocks·accent_first_screen·card_max_items·overflow·hidden_by_fixed를 우선 보고 글자 수 항목은 레퍼런스 측정값과 비교한다.
   - 레퍼런스도 같은 스크립트로 재서 우리 값과 표로 비교하면 설득력이 있다.
5. **사용자 캡처와 전후 비교.**
   - 사용자가 불만을 말한 화면(사용자 캡처 또는 같은 폭으로 찍은 이전 버전)과 새 버전을 나란히 둔다.
   - 검사 서브에이전트(model: opus)에게 아래 '까다로운 실제 사용자' 지시로 예/아니오만 받는다.
   - 하나라도 '아니오'면 3으로 돌아간다.
6. **보고.** 전후 숫자표(검사 스크립트 항목별 전→후) + 서브에이전트 예/아니오 결과. "고쳤어요"는 실제 390px 브라우저로 눌러 본 뒤에만.

## 3. 검사 서브에이전트 지시 (LLM 점수 금지)

점수(8/10 같은)를 묻지 않는다. 점수는 관대하고 사용자 눈과 안 맞았다(2026-10-21).

```
너는 이 화면을 처음 폰으로 연 까다로운 실제 사용자다. 디자이너가 아니다.
토스·당근·네이버 지도를 매일 쓴다. AI가 만든 것 같은 화면을 싫어한다.
[이전.png]와 [이후.png]를 본다(같은 390px 폭). 아래에 예/아니오로만 답하고, 아니오면 이유 한 줄.
1. 이후 화면이 이전보다 확실히 덜 복잡한가?
2. 3초 안에 이 화면이 뭘 하는 곳인지, 내가 뭘 누르면 되는지 알겠나?
3. 한 문장 안에 색이나 굵기가 섞인 곳이 없나?
4. 주황(강조색)이 주 버튼 말고 거의 안 보이나?
5. 작아서 안 읽히는 글자가 없나?
6. 카드들이 같은 규칙으로 보이나(크기·내용량)?
7. 토스·당근 같은 실제 앱 화면 옆에 둬도 어색하지 않나?
8. 사용자가 "끔찍하다"고 했던 이전 화면의 문제가 이후 화면에 남아 있지 않나?
```
- 서브에이전트에게 우리가 무엇을 고쳤는지 알려 주지 않는다(블라인드).
- 이미지 두 장의 순서를 섞어 '어느 쪽이 나은가'도 한 번 묻는다. 새 버전이 못 이기면 실패.

## 4. 이 스킬이 다른 스킬과 겹치지 않게
- 방향·글꼴 고르기 등 새 시각 정체성 만들기: `frontend-design`(Anthropic 원본과 같은 본문).
- 사이트 전체 감사·점수: `design-review`(gstack, AI Slop 블랙리스트 11개).
- 이 스킬: 이미 있는 화면을 '덜 AI 같게' 고치는 순서, 숫자 기준, 한국 모바일 레퍼런스, 사용자 전후 비교.

## 5. 금지
- Anthropic API 호출 금지. 검사는 Playwright 측정 + Claude Code 서브에이전트만.
- 이미지 생성(Codex·생성 모델) 금지. 레퍼런스는 실제 캡처.
- 검사 숫자를 맞추려고 측정만 피하는 꼼수(글자를 이미지로 굽기, 색을 채도 44%로 낮추기) 금지.

## 움직임·영상·소리 숫자 검사 (2026-10-31)
왜: 3주 교정 341건 중 디자인·영상·소리 품질이 43건으로 가장 많았다("끊겨", "애니메이션 빠름", "음악 너무 커", "음성 끊김", "냅다 시간만 늘림", "같은 음악 반복"). 눈·귀 대신 숫자로 잰다.
- 움직임: `python3 scripts/motion_check.py <url> [--click 선택자 ...]` — 폰 크기·CPU 4배 느리게, 끊긴 프레임(25ms 초과) 5% 이하·p95 25ms 이하, 애니메이션 120~600ms.
- 영상·소리: `python3 scripts/av_check.py <파일> [--bgm 배경음악 --voice 음성]` — 음량 -20~-12 LUFS, 피크 -1dBTP 이하, 중간 무음 0.6초 이상 0곳, 정지 화면 15% 이하, 60초 미만 배경음악 루프 반복 금지, 배경음악은 음성보다 12dB 이상 작게.
- ram-proxy 훅이 화면 파일 수정 후 캡처 미확인, 영상·소리 생성 후 av_check 미실행이면 완료 보고를 막는다.
- 숫자 통과는 최소 조건이다. 영상은 프레임을 뽑아 직접 보고, 화면은 캡처를 직접 본다.
